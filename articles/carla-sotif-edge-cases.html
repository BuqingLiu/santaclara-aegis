用 CARLA 构建 ISO 21448 (SOTIF) 边缘场景：从 0 到可复现合规证据

技术干货 · 面向功能安全 / SOTIF 工程师、AV 算法与 V&V 团队

1. 为什么 SOTIF 边缘场景是 AV 落地的硬骨头

ISO 21448（SOTIF，预期功能安全）关注「系统在无故障情况下，因性能局限或可预见误用导致的危害」。它的核心证据不是「代码没崩」，而是「我们在大量未知不安全 / 已知不安全场景下验证过系统行为」。难点在于：这些场景（遮挡行人、极端光照、非常规切入）很难在真实道路上有成本地采集，而手工在仿真里搭一个又慢又不可复现。

2. 为什么用 CARLA

  • 开源可批量化：脚本驱动，一次定义、千次重放；
  • 确定性：固定随机种子即可 100% 复现同一帧的同一行为——这是合规证据的前提；
  • 可观测：每一步都能导出 ego / 行人 / 车辆的遥测（位置、速度、加速度、标签），直接喂给 SOTIF 触发条件分析。

3. 一个具体场景：路口行人遮挡 AEB

以「路口右侧车辆遮挡、行人横穿、ego 触发 AEB」为例。我们用固定 seed=42 生成，关键遥测时序如下（单位 km/h）：

t (s)ego 速度事件
00.0起步
231.2正常巡航
448.6接近路口，右侧卡车遮挡
622.4行人检出，AEB 介入
80.0刹停，未碰撞

这段时序物理自洽：加速→遮挡期无法检出→行人露出后 AEB 减速→最终刹停。把它存成 CSV，就是一条可审计、可复现的 SOTIF 证据样本。

4. 23 类场景如何覆盖 SOTIF 触发条件

单一场景不够。我们把边缘场景按 SOTIF 触发条件归类为 23 类（遮挡、切入、极端光照、湿滑路面、非常规道路使用者等），每类都配套：

  • 遥测 CSV（ego + 关键交通参与者）；
  • 可复现 CARLA 脚本（带 seed）；
  • 合规标注（映射到 CA DMV / ISO 21448 / FMVSS 的判定项）。

5. 复现与合规标注的最小实践

# 复现单个场景（伪代码）
python run_full_auto.py --scenario pedestrian_occlusion --seed 42
# 导出遥测
python export_telemetry.py --out telemetry.csv
# 合规检查（全 PASS 即视为该触发条件下行为可接受）
python validate_compliance.py --standard ISO21448

关键是确定性：同样的 seed 与场景定义，任何审核员跑出来都应该是同一结果——这才是 SOTIF 证据能被认证机构（TÜV SÜD / DEKRA 等）接受的基础。
